# 配達収支 β版（ローカル検証用）

売上・経費・カレンダー・お釣りの4画面を持つ、単一HTMLのブラウザアプリです。サーバーへのデータ送信や端末間同期はありません。

## 今回の変更

- 保存キー `deli` と、従来の `days` / `exp` / `goal` / 任意の `cats` を維持します。起動時に保存・初期化・自動変換は行いません。追加属性も通常の保存で維持します。
- 読み込み例外・壊れたJSON・想定外の構造を検出した場合、警告を表示し、売上・経費の書き込みを止めます。読み込みに失敗した状態を「初回起動」にはしません。
- 保存はコピー上で準備し、localStorageへの書き込みと読み戻しが成功した後に画面の保存済みデータを更新します。容量不足等で保存できなければ成功表示をせず、入力を残して書き込みを止めます。
- 保存後の読み戻しに失敗した場合は「保存結果未確認」として止めます。この場合は書き込み自体が済んでいる可能性があるため、JSONの内容を確認してください。
- 既存日の上書きは、変更前後の売上・件数・時間を確認します。全欄を空にして保存しても記録を削除しません。削除は対象と金額を確認した場合だけ行います。
- 経費は1件ずつ確認して削除します。旧データにIDの重複があっても対象1件だけを削除します。「項目を追加」に削除処理が重なっていた不具合も修正しました。
- 別タブの変更を検出した場合、古い内容で保存しません。Web Locks対応環境では本修正版のタブ同士の保存を直列化します。非対応ブラウザ・旧版との同時編集を完全には防げないため、複数タブで同時編集しないでください。
- 未保存の入力がある状態で日付やタブを切り替える際は確認します。目標金額は入力欄を離れたときに保存します。OSによるブラウザ強制終了時の確認表示は保証できません。
- 経費項目名などの保存文字列をHTMLとして実行しないように表示します。

## JSONバックアップ

画面上部の「JSONバックアップ」から、**その時点でブラウザに保存されているデータ**を書き出します。未保存の入力は含みません。ブラウザのダウンロード・「ファイル」等で保存完了を確認してください。

ファイルには、`storageKey: "deli"`、書き出し日時、`data`（解析済みの保存データ）、`raw`（localStorageに入っていた原文）、`valid`（形式検証結果）を含めます。壊れたJSONも取得可能なら原文のまま `raw` に残します。保存領域の読み取り自体が拒否される場合や保存データがない場合は、空のバックアップを成功扱いしません。

**JSONの読み込み・復元画面は今回追加していません。** 壊れたデータが見つかってもサイトデータの消去や初期化はせず、まずファイルを確保してください。

## ローカルで開く

このフォルダで次を実行し、`http://127.0.0.1:8765/` を開きます。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

`file://` で直接開く方法は保存動作がブラウザによって異なるため、検証にはHTTPのローカルサーバーを使用します。公開ページの保存データとはオリジンが異なり、共有されません。

## ローカルテスト

Node.jsとnpmがある環境で実行します。Playwrightはテスト専用であり、アプリの実行に外部ライブラリは不要です。

```sh
npm install
npx playwright install chromium
npm test
```

既存のChromium系ブラウザを使う場合は、`BROWSER_EXECUTABLE` に実行ファイルの絶対パスを指定できます。`TEST_EVIDENCE_DIR` を指定すると、架空データのJSONとモバイル表示のスクリーンショットを書き出します。

テストは127.0.0.1の一時サーバーと独立した一時ブラウザコンテキストを使います。実際のブラウザプロファイルや公開ページのデータは使いません。確認範囲は、保存互換性・読み書きエラー・上書き／削除・競合・JSON書き出し・4画面・320〜430pxのモバイル表示です。

ChromiumでiPhone風の画面サイズやUAを指定してもSafariの検証にはなりません。Android Chrome・iPhone Safari実機でのキーボード、ファイル保存先、アプリ切り替え後の表示を、公開前に確認してください。

## Discordメンバー向けβ公開時の注意（今回公開しません）

- 通常のAndroid Chrome／iPhone Safariで開き、Discord内蔵ブラウザやシークレット／プライベートモードでの継続利用は避けます。ブラウザを変えると保存領域も変わります。
- ブラウザのサイトデータ削除、端末の空き容量不足、ブラウザ側のデータ整理などで保存内容を失う可能性があります。localStorageだけを唯一のバックアップにしないでください。
- URLのスキーム・ホスト名・ポートが同じなら、パスが違っても `deli` を共有します。**本番とβは別オリジンのHTTPSで公開**してください。同じGitHub Pagesドメインの別パスだけでは保存領域を分離できません。
- リポジトリ内の `deli (1).index.html` は旧版のままです。同じ `deli` に書き込むため、βの入口として配布せず、旧版と修正版を同じ保存領域で併用しないでください。
- Androidではダウンロード通知／Downloads、iPhoneではSafariのダウンロード一覧／「ファイル」で、JSONの保存完了を確認してください。保存ダイアログのキャンセルはアプリ側では検知できません。
- 書き込み停止の警告が出たら、未保存の入力を控え、取得可能なJSONを確保してからブラウザ設定等を確認してください。初期化やサイトデータ消去はしないでください。

参考：[Web Storage仕様](https://html.spec.whatwg.org/dev/webstorage.html)、[Chromeのシークレットモード](https://support.google.com/chrome/answer/95464?co=GENIE.Platform%3DAndroid&hl=ja)、[WebKitのストレージ方針](https://webkit.org/tracking-prevention/)。
